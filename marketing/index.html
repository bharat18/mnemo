Architecture

5 layers of structured
project memory

Inspired by bioinformatics GTF files — only the functional regions, none of the filler.

🧬
L1 — Exon Layer
Key decisions, constants, open problems, rejected approaches. Only functional regions — no greetings, no re-explanations.
like GTF exons
🧠
L2 — Node Layer
Associative memory. Type "LocalAIPanel" and Claude knows its file path, decisions, connections — no re-explaining.
like brain memory
📊
L3 — Diff Layer
How thinking evolved. v1 was Gemma3:4b, v2 is phi4-mini — Claude knows why it changed, not just what it is.
like git history
🛡️
L4 — Failure Memory
Every failure stored with trigger words. Claude automatically warns before repeating any past mistake. Miss nothing.
UNIQUE — nowhere else
🌐
L5 — Dependency Web
Blast radius tracking. If TrialManager changes, Claude knows that MainApp startup and LicenseDB both break.
like protein networks

How It Works

Three commands.
Full context. Forever.

📋
Export your chat
Open export_chat.js in browser console on any Claude.ai page. One click downloads your full conversation as .md
F12 → paste → Enter
⚙️
Run the indexer
One command compresses your chat into a structured 5-layer YAML file. Supports OpenAI and Anthropic API.
python indexer.py chat.md
📎
Upload & continue
Attach chat_gtf.yaml to a new Claude.ai chat. Paste system_prompt.md. Claude has full context instantly.
Upload → Paste → Done
🛡️
Never repeat mistakes
Claude checks Failure Memory before every response. If a trigger word matches, it warns you automatically.
Automatic · Always on
